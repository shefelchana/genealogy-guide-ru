# Другие указатели: что дают и где врут

Порядок — от дешёвого к дорогому. Каждый указатель записывай в журнал: что искал, какие формы, сколько нашлось, что покрыто.

| Указатель | Что даёт | Ловушки | Навык |
|---|---|---|---|
| **j-roots, темы местечек и уездов** | фамилия → дело → раздел (местечко, волость, цех) → PDF | спойлеры не видны в innerText; поиск только под входом; один список в нескольких темах | `references/j-roots.md` |
| **j-roots, Фамильный навигатор** | кто уже искал эту фамилию, что нашёл, какие шифры назвал | чужие выводы — гипотезы; проверять их шифры по сканам | этот навык |
| **JewishGen, базы по регионам** (Ukraine, Romania/Moldova, Belarus, Lithuania; JRI-Poland) | строка записи: имя, отчество, возраст, место, архив/фонд/дело, иногда кадр | лимит выдачи около 50 строк на набор; поля отца/матери в браках путаются; фонетический поиск ловит много шума | `searching-jewishgen` |
| **JGFF (JewishGen Family Finder)** | кто ещё ищет фамилию и в каком местечке; проверь **до** поста на форуме — ответ может уже быть | это указатель исследователей, а не документов; нужен бесплатный вход | `searching-jewishgen` |
| **KehilaLinks местечка** (kehilalinks.jewishgen.org) | страница местечка: выписанные списки, фото, ссылки, часто контакт исследователей; вместе с JGFF работает как «магнит» для родни | содержание зависит от волонтёра; выписки вторичны | `searching-jewishgen` |
| **Ukraine Research Division, страница местечка** | что по местечку уже выписано и выложено, кто ведёт местечко (Town Leader) [по выдаче] | список выписанного отстаёт от ежемесячных выгрузок | `searching-jewishgen` |
| **JRI-Poland, список фамилий местечка** (`jri-poland.org/town-surnames-list/<город>/`) | все фамилии, которые встречаются в проиндексированных записях города (Лодзь — 3297 фамилий) [по выдаче] | только проиндексированные годы; написание польское | `searching-jewishgen` |
| **IGRA, All Israel Database** (genealogy.org.il) | израильские базы; на странице поиска — счётчики совпадений в JewishGen и Gesher Galicia (через API) [по выдаче: объявление IGRA] | нужна бесплатная регистрация [по опыту, не проверено]; счётчик — не запись, переходи по ссылке | — |
| **genealogyindexer.org** | полнотекст по справочникам, адрес-календарям, спискам потерь | OCR теряет первую букву и путает буквы; известные строки бывают не проиндексированы; ноль ничего не значит | `verifying-genealogy-findings` |
| **Базы погромов** (jewishpogroms.info, pogrom.amhazikaron.org) | фамилия → дело ДАКО Р-3050 и др., 1917–1922 | только латиница (Липес); база неполна | `searching-pogrom-records` |
| **Яндекс «Поиск по архивам»** | распознанный рукописный текст дел ряда архивов | распознавание даёт искажённые формы; покрытие архивов неполное | `searching-yandex-archives` |

## Общие правила

- **Указатель — ⚪ подсказка.** Документом становится только лист, прочитанный по скану.
- **Не считай повторы.** Тот же список, перепечатанный в трёх темах или базах, — одно свидетельство.
- **Отрицательный результат по указателю слабый.** Он говорит «в расписанной части нет», а не «в деле нет». Для вывода нужны четыре условия отрицательного вывода (`verifying-genealogy-findings`): границы источника, формы, способ, индекс или документ.
- **Ищи по месту, когда фамилия не находится**: какие дела по местечку вообще расписаны, а какие нет. Нерасписанные — в план сплошного чтения.
- **Новая фамилия → реестр.** Сначала сверь её с реестром непросмотренных разделов, потом иди в указатели.
