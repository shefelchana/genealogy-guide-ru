# Other indexes: what they provide and where they mislead

The order runs from cheap to expensive. Record every index in the log: what you searched for, which forms, how many hits, what is covered.

| Index | What it provides | Traps | Skill |
|---|---|---|---|
| **j-roots, shtetl and uezd topics** | surname → file → section (shtetl, volost, guild) → PDF | spoilers are not visible in innerText; search only when logged in; one list appears in several topics | `references/j-roots.md` |
| **j-roots, Family navigator** | who has already searched for this surname, what they found, which reference codes they cited | other people's conclusions are hypotheses; check their reference codes against the scans | this skill |
| **JewishGen, regional databases** (Ukraine, Romania/Moldova, Belarus, Lithuania; JRI-Poland) | a record row: name, patronymic, age, place, archive/fond/file, sometimes the frame | results capped at about 50 rows per dataset; father/mother fields in marriages get mixed up; phonetic search catches a lot of noise | `searching-jewishgen` |
| **JGFF (JewishGen Family Finder)** | who else is searching for the surname and in which shtetl; check **before** a forum post, since the answer may already be there | an index of researchers, not of documents; a free login is required | `searching-jewishgen` |
| **KehilaLinks for the shtetl** (kehilalinks.jewishgen.org) | the shtetl's page: transcribed lists, photos, links, often a researcher contact; together with JGFF it works as a "magnet" for relatives | content depends on the volunteer; transcriptions are secondary | `searching-jewishgen` |
| **Ukraine Research Division, shtetl page** | what has already been transcribed and posted for the shtetl, who runs it (Town Leader) [from search results] | the list of transcribed material lags behind the monthly uploads | `searching-jewishgen` |
| **JRI-Poland, town surname list** (`jri-poland.org/town-surnames-list/<town>/`) | all surnames occurring in the town's indexed records (Łódź: 3,297 surnames) [from search results] | only indexed years; Polish spelling | `searching-jewishgen` |
| **IGRA, All Israel Database** (genealogy.org.il) | Israeli databases; the search page shows match counts in JewishGen and Gesher Galicia (via API) [from search results: an IGRA announcement] | free registration needed [from experience, not verified]; a count is not a record, follow the link | none |
| **genealogyindexer.org** | full text of directories, address calendars, casualty lists | OCR loses the first letter and confuses letters; known lines are sometimes not indexed; a zero means nothing | `verifying-genealogy-findings` |
| **archival.name** (since 8.10.2026; free; built by one person) | a combined index compiled by AI: inventories (names in file titles), the 1897 census, the family cards of the 1926 census for the Ukrainian SSR, files on relief to victims of pogroms 1917–1938, merchants of the guberniyas, directories, metrical books; from a card — a link to the scan and to the file on Commons. Search by URL: `archival.name/ru/search/?q=<surname>&m=bm&t=<town in Latin script>&tr=g` (`m=bm` — "sounds like", `tr=g` — guberniya around 1900). JSON: `/api/everything?q=…&m=bm&sur=<surname>&msur=bm&t=<Town>&tr=g` — counts by collection; `/api/archives-finding-aids/search?nm=<name>&nmm=bm&pl=<Town>&plr=g` — inventories | **the AI distorts names** (the card shows one form, the scan another; Latin spelling of the Polish type; file titles in machine translation) — assert nothing from the index, only from the scan; an inventory row leads to the inventory, and the file may not be digitised; rows take 10–20 s to load; "database busy" — retry after ~20 s; **parallel requests return empty answers** — one at a time, with pauses; a control query first; whether a login is needed for full rows — [verify] | this skill; `verifying-genealogy-findings` |
| **Pogrom databases** (jewishpogroms.info, pogrom.amhazikaron.org) | surname → DAKO file R-3050 and others, 1917–1922 | Latin script only (Lipes); the database is incomplete | `searching-pogrom-records` |
| **Yandex "Search in Archives"** | recognised handwritten text of files from a number of archives | recognition produces distorted forms; archive coverage is incomplete | `searching-yandex-archives` |
| **ANU — Museum of the Jewish People** (Tel Aviv; dbs.anumuseum.org.il) | surname articles, community histories, family trees sent in by other people — look for **your own family's tree**: relatives may have sent it in, with dates you lack | the search field reacts to typing, not to a pasted value; **search by URL**: first open `/skn/he` (or `/skn/en`), then `/skn/he/c6/BH/Search#query=<word>`; changing only the part after "#" on an open search page does not rerun the search — load the address again; scripts get 403, work in an ordinary browser; Hebrew words that are also common nouns give hundreds of fuzzy hits (checked November 2026) | — |
| **Inventories on Wikisource** | file titles, sometimes with names (personal files, court cases, petitions) | a title does not list everyone inside the file | `ukrainian-archives-on-commons` |

## General rules

- **An index is a ⚪ hint.** Only a folio read from the scan becomes a document.
- **Do not count repeats.** The same list reprinted in three topics or databases is one piece of evidence.
- **A negative result from an index is weak.** It says "not in the itemised part", not "not in the file". For a conclusion you need the four conditions of a negative conclusion (`verifying-genealogy-findings`): source limits, forms, method, index or document.
- **Search by place when the surname cannot be found**: which files for the shtetl have been itemised at all, and which not. The unitemised ones go into the plan for straight-through reading.
- **New surname → registry.** First check it against the registry of unread sections, then go to the indexes and databases.
