# Каталоги исследования: источники, персоны, карточка, библиотека

Каталоги ничего не доказывают сами — они **показывают**, что уже найдено и насколько это прочно. Поэтому главное правило: брать данные только из файлов проекта (журнал находок, ПЕРСОНЫ, ГИПОТЕЗЫ, реестр источников) и не поднимать уровень.

## 1. Каталог источников

Одна строка — один документ или один честный ноль.

| Поле | Как заполнять |
|---|---|
| шифр | архив, фонд-опись-дело (лист / кадр) или сайт и коллекция. Указатель и скан той же записи — **одна** строка: индекс — не второй источник |
| год | год документа, не год события |
| тип | одно короткое слово из набора: метрики, ревизии, переписи, ЗАГС, военные, эвакуация, справочники, суд и учёт, газеты, кладбища, ДНК — по нему фильтр |
| о ком | имена так, как в документе, плюс наше отождествление |
| что дал | одна фраза: что из этого документа следует |
| уровень | 🟢 🟡 ⚪ 💭 🔴 — как в файлах проекта; для отрицательного результата — «ноль с охватом» |

**Ноль с охватом** — тоже строка: «том 1 прочитан целиком — Мордко нет», «все рождения 1891 г. прихода прочитаны — пары нет». Ноль без охвата («поискала, не нашла») в каталог не идёт: это не результат, а запись журнала поисков. Подробно — руководство, раздел «Ложный ноль».

Для витрины — массив `sources` (схема — `building-research-showcase/references/data-schema.md`). Для проекта — таблица в `РЕЕСТР-ИСТОЧНИКОВ.md` с дополнительными полями «где скан», «где вывод (§)», «когда смотрели».

## 2. Каталог персон

Одна карточка — один человек: имя (как в документах), годы, роль одной строкой («Бердичев → Москва · прадед»), линия, **уровень главной связи**. Уровень относится к связи «сын такого-то / жена такого-то», а не к человеку: имя может быть 🟢 по метрике, а родство с нашей семьёй — 💭. Так видно, кто держится только на семейной памяти.

Тёзки: если в проекте есть два человека с одним именем, в карточке — различающий признак (год, место, отчество). Таблица «кто есть кто» — навык `organizing-genealogy-research`.

## 3. Карточка одного человека (как на сайтах-деревьях)

- **Факты** слева: имена и их варианты, рождение, смерть, сословие / приписка, линия. У каждого — уровень.
- **Хронология**: год — событие — источник — уровень. Строка без источника не ставится; если событие известно только по рассказу — источник «семейная память», уровень 💭.
- **Семья**: родители, супруг(и), дети, с пометкой спорного.
- **Источники**: короткий список шифров.
- **Открытые вопросы**: спорное и неизвестное — отдельно, а не спрятано в хронологии. Это то, чем карточка лучше обычного профиля на сайте-дереве.

Выбирайте для карточки человека с самой богатой хронологией: она лучше всего показывает формат.

## 4. Библиотека документов

- **Схема папок** проекта — как есть сейчас (журналы, персоны, гипотезы, архив по линиям, фото «оригиналы / рабочие», ДНК, бэкап).
- **Правило имени файла**: `Архив_фонд-опись-дело_год_о-ком_что.расширение` — шифр впереди ищется поиском, год рядом показывает эпоху.
- **Карточка документа**: шифр, год, тип, о ком, где нашли и когда, есть ли скан, статус (найден в указателе → скан скачан → прочитан → сверен по кадру → записан → уровень поставлен), где вывод.
- Правило 3-2-1 для копий.

## Обезличенная версия

Для публичного примера заменяйте имена, места и шифры целиком (не одну букву), шифры помечайте [усл.]. Структура и типы документов остаются настоящими — в этом смысл примера.

## Проверка перед сдачей

- Каждая строка с 🟢 имеет шифр.
- Нет двух строк на одну запись (индекс + скан).
- Типы в каталоге — из одного набора слов (иначе фильтр рассыпается).
- В публичной версии нет настоящих имён (сборка с `--forbid`).
