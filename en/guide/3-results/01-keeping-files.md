# Keeping files

What this section covers: how to organize a research folder so that nothing is lost, nothing is searched twice, and it is clear what each conclusion rests on. Plus naming of scans and backups.

---

## 1. One folder — several "living" files with different roles

It is convenient to keep everything in one project folder on your computer. Inside — several text files, each with its own role. Ready-made blanks are in [../../templates/](../../templates/finding.md).

| File | What is in it | Template |
|---|---|---|
| **Dossier (finds log)** | Each find: date, source with archival reference, verbatim quotation, what it changes | [finding.md](../../templates/finding.md) |
| **Persons** | A directory of people: everything known about each person in one place. A separate "circle" line: witnesses, partners, neighbours, fellow travellers (see the FAN principle in [Standard of proof](02-standard-of-proof.md)) | — |
| **Hypotheses** | Each guess — with grounds, weak points, a way to check and a status: 🟢 confirmed / 🟡 open / 🔴 withdrawn | [hypothesis.md](../../templates/hypothesis.md) |
| **Research log** | Where, what and how you searched, **including empty results** | [research-log.md](../../templates/research-log.md) |
| **Source register** | Archive, fond–inventory–file, where the scan is, what has been read, date of access | [source-register.md](../../templates/source-register.md) |
| **History** | A coherent text for relatives, separate from working notes | see [Writing the family history](03-family-history.md) |

Why empty results are so important. The FamilySearch Wiki ("Research Logs") considers records of empty searches the main benefit of a log: without them in a month you will repeat the same search. Advice from the same place: do not leave a cell blank but write "Ø" and **spell out what the zero means** — the surname is not there at all, the needed given name is not there, or there is no person of the needed age.

## 2. Lines of inquiry and subfolders

When the lines of inquiry multiply (different branches of the family, different archives), set up a "Branches" folder and a subfolder for each line. In the subfolder — scans, crops and working notes for that line.

If the common finds log grows, divide it by branches, and leave in the common file only a table of contents and summaries.

It is useful to keep a short "Start here" or "Current direction" file: what we are searching for now, what has been excluded, where we stopped. In half a year (or for a new helper, human or AI) this will save hours.

## 3. How to record a find

The minimum for each find:
- **the document's archival reference**: archive, fond–inventory–file–folio, record number;
- **where the scan is**: site, film, frame number, direct link;
- **a verbatim quotation** in the original spelling (with the yat and the hard sign);
- **a translation or explanation**, if needed;
- **confidence of reading**: confident / unconfident, what hinders;
- **whether it was checked against the scan** or so far only against the index;
- **the date of the record**.

Record a find **at once**, at that very moment. A deferred record is a lost record.

FamilySearch ("Cite Your Sources") names five elements of a citation: author, title, where it is held or by whom published, date, the exact place (page, frame). For online materials add the date of access and the page address. It is useful to add a short assessment of reliability: whether it agrees with other documents, whether the date is not a calculated one.

## 4. How to name scans and crops

The file name should itself say what is inside. A working scheme:

```
year_archive-reference_frame_who-what.png
1895_НАРМ-211-11-238_к841_брак-Вайнберг-Репетур.png
```

(In the example, НАРМ is ANRM, the National Archives of the Republic of Moldova; «к841» is frame 841; «брак» is "marriage".)

General rules of naming (from articles on the preservation of digital archives; information from a search snippet, the pages were not opened):
- only letters, digits, hyphen and underscore, no spaces or punctuation;
- the scheme "SURNAME_Given-name_what_when_where" works too;
- the same thing always the same way.

Keep the **original frame** whole and separately — a crop of the needed line. The crop is convenient for reading and for text; the original is needed so that anyone can check.

## 5. Backups by the 3-2-1 rule

Advice from the FamilySearch blog ("Preserving Electronic Information"):
- every important file should have **no fewer than three copies**;
- on **two different types** of media (for example, the computer's disk and an external disk or the cloud);
- at least **one copy off the premises**.

Backing up is not a one-off action. **Once a year** check that the copies open, and move old formats to new media. Tell relatives where the archive is. And from the same source: "without order there is no preservation" — first put things in order, then copy.

Before large edits (rewriting the history, rebuilding the tree) make a separate copy.

## 6. The tree is only for what is confirmed

An online tree (MyHeritage, FamilySearch, Geni and others) is seen by other people and copied to their own. Therefore:
- into the tree — only what is confirmed by a document;
- keep hypotheses in the hypotheses file;
- every event in the tree has a link to a source;
- do not publish living people without their consent.

Which platform to choose — in [Tree platforms](../2-reference/16-tree-platforms.md).

## 6a. Two more useful files

- **A register of partly read files.** A file read for one surname later passes itself off as "viewed" for another. Record: the file, which sections and frames have been read, for which surname you searched, what remains. When a new surname appears, look here first ([Community surname indexes](../2-reference/08-surname-indexes.md)).
- **Contradictions.** When inconsistent information about a person has accumulated, it is convenient to draw a map: in the centre the person, branches are the sources, arrows show which statements agree and which dispute (a technique of Ron Arons from the book "Mind Maps for Genealogy", 2014) [from search snippet]. In a file this can be a table "statement — source — agrees with — disputes with".

## 7. If you work with an AI assistant

Everything important must live **in files, not in the memory of the conversation**. A new session does not remember the previous one. Before a new search the assistant first searches the project files for what is already known. Set up a "Continue from here" file: the current question, what has been done, what awaits the human, the next step. Details — [Working with agents](../1-ai-search/03-working-with-agents.md), section 7, and [AI tools](../1-ai-search/05-ai-tools.md).
