# Community surname indexes: index first, page-by-page reading second

What this section covers: where to find ready-made "surname → archival file → shtetl" indexes compiled by volunteers and projects, and how to get from an index line to the scan. An index tells you in a minute which file and which section a surname appears in; paging through without one takes hours.

Markers: **[checked]** — the page was read or the query was run (October 2026); **[from search snippet]** — information taken from search results; **[unverified]** — exactly that.

---

## 1. When you need this

- Before reading a revision list, census, family list (*posemeinyi spisok*) or metrical book straight through for a surname.
- When a **new surname** appears (a wife, a brother-in-law, a neighbouring branch).
- When a file has already been read for another surname and it is unclear whether all its sections were looked at.

The main rule: **an index is a pointer, not a document.** It usually gives no pages, names or ages. Every hit is checked against the scan.

## 2. First, your own register of unread material

If the new surname could appear in a file you have already handled, **finish reading that file first**: it is the cheapest find there is. A typical case: a revision-list file was read only in the section for one shtetl, and an index later shows the surname you need in a neighbouring section of the same file.

Keep a **register of partly read files**: the file, which sections have been read, and which surname you were searching for. The template is in the skill `using-community-surname-indexes` ([../../../skills/](../../../skills/)).

## 3. Which indexes exist

| Index | What it gives | Pitfalls |

| **The "Jewish Roots" forum** (*Evreiskie korni*; forum.j-roots.info; Russian-language site), shtetl and uezd threads | volunteers have itemised files: "fond-inventory-file → frames by shtetl → surnames", with links to PDFs | lists are hidden under "Show" spoilers; forum search works only after logging in [checked]; one list is repeated in several threads |
| **"Jewish Roots", Surname Navigator** (*Familnyi navigator*; Russian-language site) | a table of contents of surname threads: who has already searched this surname, what they found, which archival references they named [checked] | other people's conclusions are hypotheses; check archival references against the scans |

| **JewishGen Family Finder (JGFF)** | who else is searching the surname and in which shtetl | an index of researchers, not of documents; free login required |
| **KehilaLinks for the shtetl** and the shtetl page at the JewishGen Ukraine Research Division | transcribed lists, photos, contacts of researchers; who runs the shtetl (Town Leader) | content depends on the volunteer |

| **IGRA, All Israel Database** (genealogy.org.il) | Israeli databases; since August 2026 the results show match counts in JewishGen and Gesher Galicia [checked: IGRA announcement] | free registration needed [unverified]; a count is not a record |
| **Genealogy Indexer** (genealogyindexer.org) | full text of directories, address calendars, memorial books, casualty lists | OCR loses the first letter; a zero result means nothing |
| **Pogrom databases** | surname → DAKO file R-3050 (State Archive of Kyiv Oblast) and others, 1917–1922 | incomplete; see [Pogroms 1918–1922](11-pogroms-1918-1922.md) |
| **Yandex "Archive Search"** (*Poisk po arkhivam*; Russian-language site) | recognised handwritten text of files in a number of Russian archives | recognition distorts forms; no Ukrainian archives |
| **Inventories on Wikisource** (Vikidzherela, Ukrainian-language) | file titles, sometimes with names | a title does not list every person in the file |
| **Indexes inside the files themselves** | in files scanned by A. Krakowski there are sometimes alphabetical indexes and name lists — for example, Cyrillic indexes to the metrical books of big cities; the JewishGen Ukraine Research Division transliterates them [from search snippet] | a year's index may be incomplete |

**Indexes keep growing.** In 2026 the JewishGen Ukraine Research Division was adding 100–150 thousand records a month [checked: jewishgen.org/ukraine]. Genealogy Indexer mails out a list of new sources. A negative result from an index is valid only on the date of the search: write down the date and repeat the search after updates.

**Annual indexes to metrical books contain errors.** According to JRI-Poland's experience, annual alphabetical indexes are accurate to about 90%: some records did not make it in, and some surnames were misread [attributed to JRI-Poland, unverified]. A year's index is no substitute for the book itself.

## 4. How to search

1. **A list of spellings** — before the first query: Cyrillic and Latin, different root vowels, "-sky/-tsky", "-man/-mann", **without the first letter** (indexes and OCR lose it), without "y". Details in [Names, surnames, spellings](03-names-spellings.md).
2. **Indexes in turn, from cheap to expensive**: your own register → forum lists → JewishGen and JGFF → full-text corpora → pogrom databases (for 1917–1922) → Yandex "Archive Search".
3. **Check JGFF before you post on a forum**: the answer may already be there, and a "co-researcher" may turn up.
4. If the surname cannot be found, **search by place**: which files for the shtetl have been itemised at all, and which have not. Files that have not been itemised are candidates for page-by-page reading.

## 5. From the index to the file

1. Match the surname to the **document heading** under which it stands ("Fond 280, inventory 2, file …" → the shtetl's section). A single forum post can contain a dozen files in a row — check with your own eyes.
2. Find the scan: a PDF on Wikimedia Commons via the link in the post (the full address is in the link itself; the visible text is sometimes truncated) or by title. Search by words, not by the archival reference alone: the files are named inconsistently.
3. Check by archival reference whether the file has been put online, and where: "Kachyni Inspector" (*Kachynyi Inspektor*; inspector.duckarchive.com) is a volunteer consolidated index of files from Ukrainian archives published on FamilySearch, Commons, archive websites and elsewhere [checked]. An empty answer does not mean there is no scan.
4. Read the **whole section**, not just the frame with the surname. "Frames" in a post are PDF pages; the folios of the file are on the scan itself: give both in your note.
5. Record in the register what was read, what was not, and which surname you were searching for.

## 6. Pitfalls

- **An index loses letters**: the first one, "y", the soft sign; it confuses the Russian letters "е/э" and "и/ы".
- **A surname may turn out to be a given name** or a nickname of a person with a different surname.
- **A patronymic or a registration note instead of a surname**: "…sky meshch." means a meshchanin (townsman) of the shtetl, not a surname.
- **Repetitions are not confirmations**: one list reprinted in three threads is one piece of evidence.
- **An index is incomplete by year**: files that someone photographed are itemised. The absence of a year is a reason to check the inventory, not a conclusion that "it has not survived".

## 7. Access and courtesy

- Threads of the "Jewish Roots" forum open without logging in; search works only under an account. A person does the logging in. Without logging in you can search with an ordinary search engine restricted to the forum's site.
- If a site will not open because of the network (geo-blocking, VPN, an expired certificate), do not get around the protection: a person decides.
- Offer your own material: lists and indexes you have read help those who come after.

> **How to ask AI**
>
> - "I am looking for the surname [N] in [shtetl, uezd, guberniya]. List the indexes worth checking before paging through files, in order from cheap to expensive, and which forms of the surname to enter in each." *Check yourself:* that the indexes really exist and open. (The AI may need to read Russian-language sources.)
> - "Here is a forum post with a list of surnames [text or HTML]. Find all forms of the surname [N] and for each give the nearest file heading above it (fond, inventory, file), the section and the link to the PDF." *Check yourself:* the file heading, by eye; lists under spoilers are not lost when copying.
> - "Here is my register of files read [table]. Which files have unread sections where the surname [N] could stand?"
> - "An index line says the surname appears in file [archival reference], section [shtetl]. Find the scan of this file and the frame numbers of the section." *Check yourself:* the PDF title and section match the index.
