# Community surname indexes: index first, page-by-page reading second

What this section covers: where to look for ready-made indexes "surname → archival file → shtetl" compiled by volunteers and projects, and how to get from a line of an index to the scan. An index tells you in a minute which file and which section a surname is in; paging through without it takes hours.

The markers in square brackets ([checked], [from search snippet], [unverified] and others) are explained in the [Glossary](../0-start/06-glossary.md).

---

## 1. When you need this

- Before reading a revision, census, family list or metrical book from start to finish for a surname.
- When a **new surname** has appeared (a wife, a brother-in-law, a neighbouring branch).
- When a file has already been read for another surname and it is unclear whether all the sections have been looked through.

The main rule: **an index is a hint, not a document.** It usually does not give pages, names or ages. Every hit is checked against the scan.

## 2. First — your own register of the unread

If a new surname might be in a file that you have already held in your hands, **finish reading it first**: it is the cheapest find. A typical case: a revision file was read only in the section of one shtetl, and an index later shows the surname you need in a neighbouring section of the same file.

Keep a **register of partly read files**: the file, which sections have been read, and for which surname you searched. A template is in the skill [`using-community-surname-indexes`](../../../skills/using-community-surname-indexes/SKILL.md) (in Russian).

## 3. Which indexes there are

| Index | What it gives | Traps |
|---|---|---|
| **The "Jewish Roots" forum** (Еврейские корни; forum.j-roots.info), topics on shtetls and uezds | volunteers have itemised files: "fond-inventory-file → frames by shtetl → surnames", with links to PDFs | the lists are hidden under "Show" spoilers; searching the forum works only after logging in [checked]; one list is repeated in several topics |
| **"Jewish Roots", the Surname Navigator** (Фамильный навигатор) | a table of contents of surname topics: who has already searched this surname, what they found, which references they named [checked] | other people's conclusions are hypotheses; check references against scans |
| **JewishGen databases** by region (Ukraine, Romania/Moldova, Belarus, Lithuania; JRI-Poland) | a record line: name, patronymic, age, place, archive, sometimes the frame | results are limited (about 50 lines per set) — narrow the query; the father's and mother's fields in marriages get mixed up |
| **JewishGen Family Finder (JGFF)** | who else is searching the surname and in which shtetl | an index of researchers, not documents; a free login is needed |
| **The shtetl's KehilaLinks** and the shtetl page at the Ukraine Research Division | transcribed lists, photos, contacts of researchers; who looks after the shtetl (Town Leader) | the content depends on the volunteer |
| **The JRI-Poland list of a town's surnames** | all the surnames found in the indexed records of the town [from search snippet] | only the indexed years |
| **IGRA, All Israel Database** (genealogy.org.il) | Israeli databases; since August 2026 the results show counters of matches in JewishGen and Gesher Galicia [checked: IGRA announcement] | free registration is needed [unverified]; a counter is not a record |
| **Genealogy Indexer** (genealogyindexer.org) | full text of directories, address calendars, memorial books, casualty lists | recognition loses the first letter; a zero means nothing |
| **Pogrom databases** | surname → DAKO file R-3050 and others, 1917–1922 | incomplete; see [Pogroms 1918–1922](11-pogroms-1918-1922.md) |
| **Yandex "Search in archives"** (Яндекс «Поиск по архивам») | recognised handwritten text of files of a number of Russian archives | recognition distorts forms; there are no Ukrainian archives |
| **Inventories on Vikidzherela** (Вікіджерела, Ukrainian Wikisource) | file titles, sometimes with names | a title does not list all the people in the file |
| **Indexes inside the files themselves** | in files scanned by A. Krakovsky there are sometimes alphabetical indexes and name lists — for example, Cyrillic indexes to the metrical books of big cities; the JewishGen Ukraine Research Division transliterates them [from search snippet] | the index for a year may be incomplete |

**Indexes keep growing.** In 2026 the JewishGen Ukraine Research Division was adding 100,000–150,000 records a month [checked: jewishgen.org/ukraine]. Genealogy Indexer sends out a list of new sources. A negative result from an index is true only as of the date of the search: write down the date and repeat the search after additions.

**Annual indexes of metrical books make mistakes.** According to JRI-Poland's experience, annual alphabetical indexes are right about 90% of the time: some records did not get into them, and some surnames were misread [attributed to JRI-Poland, unverified]. The index for a year is not a replacement for the book itself.

## 4. How to search

1. **A list of spellings** — before the first query: Cyrillic and Latin, a different root vowel, "-skii/-tskii", "-man/-mann", **without the first letter** (indexes and recognition lose it), without "й". In detail — [Names, surnames, spellings](03-names-spellings.md). Don't read Russian? See [For English speakers](../0-start/08-for-english-speakers.md).
2. **Indexes in turn, from cheap to expensive**: your own register → forum lists → JewishGen and JGFF → full-text corpora → pogrom databases (for 1917–1922) → Yandex "Search in archives".
3. **Check JGFF before writing on a forum**: the answer may already be there, and a "co-researcher" may be found.
4. If the surname is not found, **search by place**: which files for the shtetl have been itemised at all and which have not. The ones not itemised are candidates for reading from start to finish.

## 5. From the index to the file

1. Match the surname with the **title of the document** under which it stands ("Fond 280, inventory 2, file …" → the section of the shtetl). One forum post can have a dozen files in a row — check by eye.
2. Find the scan: a PDF on Wikimedia Commons by the link in the post (the full address is in the link itself, the visible text is sometimes truncated) or by title. Search with words, not with a single string of the reference: files are named in different ways.
3. Check by the reference whether the file is online and where: "Kachynyi Inspektor" (Качиний Інспектор, "Duck Inspector"; inspector.duckarchive.com) is a volunteer combined index of files of Ukrainian archives published on FamilySearch, Commons, archive sites and elsewhere [checked]. An empty answer does not mean there is no scan.
4. Read the **whole section**, not just the frame with the surname. The "frames" in a post are PDF pages, while the file's folios are on the scan itself: note both in your record.
5. Write in the register what has been read, what has not, and for which surname you searched.

## 6. Traps

- **An index loses letters**: the first one, "й", the soft sign; it confuses "е/э", "и/ы".
- **A surname may turn out to be a given name** or the nickname of a person with another surname.
- **A patronymic or a registration note instead of a surname**: "…ский мещ." is a *meshchanin* of a shtetl, not a surname.
- **Repeats are not confirmations**: one list reprinted in three topics is one piece of evidence.
- **An index is incomplete by years**: the files that someone filmed are itemised. The absence of a year is a reason to check the inventory, not a conclusion "did not survive".

## 7. Access and courtesy

- The topics of the "Jewish Roots" forum open without logging in, but search works only under an account. The login is done by a person. Without logging in you can search with an ordinary search engine restricted to the forum's site.
- If a site does not open because of the network (geo-blocking, VPN, an expired certificate), do not get around the protection: a person decides.
- Offer your own: the lists and indexes you have read help the next researcher.

> **How to ask AI**
>
> *For a plain chat, add: "If you can't open a source, say so; mark fonds, villages and dates you name from memory as [from memory, verify]. Answer in English, and give names, places and archive titles in the original script in parentheses." ([why](../1-ai-search/02-prompt-library.md)). The (browser agent) label is for an AI that opens websites itself; the other prompts suit any chat.*
>
> - "I am looking for the surname [name] in [shtetl, uezd, guberniya]. List the types of indexes worth checking before paging through files, in order from cheap to expensive, and which forms of the surname to enter into each. Mark any specific indexes that you cannot open as [from memory, verify]." *Check yourself:* that the indexes really exist and open.
> - "Here is a forum post with a list of surnames [text or HTML]. Find all the forms of the surname [name] and for each give the nearest file title above it (fond, inventory, file), the section and the link to the PDF." *Check yourself:* the file title — by eye; lists under spoilers are not lost when copying.
>
> *Bad → good:* "Find everything about the surname [name]" (asks for "everything", no place or years) → "In which volunteer indexes might the surname [name] from [shtetl, uezd] stand for [years]?"
