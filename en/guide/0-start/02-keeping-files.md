# Keeping files

What this section covers: how to set up a research folder so that nothing is lost, nothing is searched twice, and it is clear what each conclusion rests on. Plus naming scans and backups. You need files from the first hour of work, which is why this section comes at the beginning.

---

## 1. One folder — several "living" files with different roles

It is convenient to keep everything in one project folder on your computer. Inside are several text files, each with its own role. Ready-made blanks are in [../../templates/](../../templates/README.md).

| File | What is in it | Template |
|---|---|---|
| **Finds log** | Every find: date, source with archival reference, verbatim quotation, what it changes | [finding.md](../../templates/finding.md) |
| **Persons** | A reference on people: everything known about each person in one place. A separate "circle" line: witnesses, business partners, neighbours, fellow travellers (see the FAN principle in [Standard of proof](../3-results/01-standard-of-proof.md)) | [persons.md](../../templates/persons.md) |
| **Hypotheses** | Every guess — with its grounds, weak points, way of checking and status: 🟢 confirmed / 🟡 open, strong version / ⚪ unverified / 🔴 rejected — [status scale](../3-results/01-standard-of-proof.md) | [hypothesis.md](../../templates/hypothesis.md) |
| **Research log** | Where, what and how you searched, **including empty results** | [research-log.md](../../templates/research-log.md) |
| **Source register** | Archive, fond–inventory–file, where the scan is, what has been read, date accessed | [source-register.md](../../templates/source-register.md) |
| **Continue from here** | One page: the current question, where you stopped, what awaits the person, the next step | [continue-from-here.md](../../templates/continue-from-here.md) |
| **History** | A connected text for relatives, kept apart from working notes | see [Writing the family history](../3-results/02-family-history.md) |

Why empty results matter so much. The FamilySearch Wiki ("Research Logs") considers records of empty searches the main benefit of a log: without them, in a month you will repeat the same search. Another tip from the same place: do not leave a cell blank, write "Ø" and **spell out what the zero means** — the surname is not there at all, the needed name is not there, or there is no person of the needed age.

## 2. Directions and subfolders

When there are many directions (different branches of the family, different archives), create a "Branches" folder and a subfolder for each direction. In a subfolder keep the scans, crops and working notes for that direction.

If the common finds log grows, divide it by branch, and leave only a table of contents and summaries in the main file.

Be sure to keep a short "Continue from here" file: what you are searching for now, what has already been excluded, where you stopped. In six months (or for a new helper, human or AI) it will save hours.

## 3. How to record a find

The minimum for every find:
- **the archival reference of the document**: archive, fond–inventory–file–folio, record number;
- **where the scan is**: site, film, image number, direct link;
- **a verbatim quotation** in the spelling of the original (with the old letters yat and yer);
- **a translation or explanation**, if needed;
- **confidence of the reading**: confident / not confident, what gets in the way;
- **whether it has been checked against the scan** or so far only against the index;
- **the date of the entry**.

Record a find **at once**, at that very moment. A postponed record is a lost record.

FamilySearch ("Cite Your Sources") names five elements of a citation: author, title, where it is kept or who published it, date, the exact place (page, image). For online materials add the date accessed and the page address. It is useful to add a short reliability rating: whether it agrees with other documents, whether the date is a calculated one.

## 4. How to name scans and crops

A file name should itself say what is inside. A working scheme:

```
year_archive-reference_image_who-what.png
1895_ANRM-211-11-238_i841_marriage-Weinberg-Repetur.png
```

(ANRM — the National Archives of the Republic of Moldova.)

General naming rules (from articles on the preservation of digital archives) [from search snippet]:
- only letters, digits, hyphens and underscores, no spaces or punctuation marks;
- the scheme "SURNAME_Given-name_what_when_where" also works;
- the same thing is always named the same way.

Keep the **original image** whole, and separately a crop of the needed line. A crop is convenient for reading and for text; the original is needed so that anyone can check.

## 5. Backups by the 3-2-1 rule

The advice of the FamilySearch blog ("Preserving Electronic Information"):
- every important file has **at least three copies**;
- on **two different types** of media (for example, the computer's disk and an external disk or the cloud);
- at least **one copy away from home**.

Backing up is not a one-off action. **Once a year** check that the copies open, and move old formats to new media. Tell your relatives where the archive is. And one more thing from there: "without order there is no preservation" — put things in order first, then copy.

Before big changes (rewriting the history, rebuilding the tree), make a separate copy.

## 6. The tree is only for what is confirmed

An online tree (MyHeritage, FamilySearch, Geni and others) is seen by other people, who copy it to their own. So:
- into a publicly visible tree — only 🟢, confirmed by a document; into a personal working tree you may put 🟡 with a "version" note ([status scale](../3-results/01-standard-of-proof.md));
- keep hypotheses in the hypotheses file;
- every event in the tree has a link to its source;
- do not publish living people without their consent.

Which platform to choose — see [Tree platforms](../2-reference/16-tree-platforms.md).

## 6a. Two more useful files

- **A register of partly read files.** A file read for the sake of one surname later passes itself off as "viewed" for another. Write down: the file, which sections and images have been read, which surname you searched for, what is left. When a new surname appears, look here first ([Community surname indexes](../2-reference/08-surname-indexes.md)).
- **Contradictions.** When inconsistent information has piled up about a person, it is handy to draw a map: the person in the centre, the sources as branches, arrows showing which statements agree and which conflict (a technique of Ron Arons from the book "Mind Maps for Genealogy", 2014) [from search snippet]. In a file it can be a table "statement — source — agrees with — conflicts with".

## 7. If you work with an AI assistant

Everything important must live **in files, not in the memory of the conversation**. A new session does not remember the previous one. Before a new search the assistant first looks through the project files for what is already known. Set up a "Continue from here" file: the current question, what has been done, what awaits the person, the next step.

**If the AI works in an ordinary chat without access to a folder** (ChatGPT, Gemini, Claude.ai without a project): you keep the files. Ask the AI to give a "Write to files" block at the end of every answer — new finds, research-log lines, changes to hypotheses, the next step — and copy it into your documents. At the start of a new conversation, paste "Continue from here" and the necessary extracts. How to ask for this — [Quick start](01-quick-start.md). Details — [Working with agents](../1-ai-search/03-working-with-agents.md), section 7, and [AI tools](../1-ai-search/05-ai-tools.md).
